# 🚗 Premium Car Rental — نظام تأجير السيارات

نظام متكامل لتأجير السيارات مبني بـ **PHP (بدون أطر عمل) + MySQL**، بواجهة عربية (RTL) فاخرة ولوحة إدارة كاملة.

---

## ✨ المميزات

### للزبائن
- تصفح السيارات مع فلترة متقدمة (الماركة، الوقود، ناقل الحركة، عدد المقاعد، السعر، التواريخ)
- صفحة تفاصيل لكل سيارة مع معرض صور ومواصفات كاملة
- حجز تفاعلي: اختيار التواريخ، الخدمات الإضافية (GPS، مقعد طفل، سائق إضافي…)، حساب فوري للسعر
- **كوبونات خصم** (جرّب: `WELCOME10` أو `SUMMER20`) + خصومات تلقائية للمدد الطويلة
- دفع (تحويل بنكي بجميع البنوك المغربية / نقداً) مع توليد **فواتير قابلة للطباعة**
- لوحة تحكم العميل: الحجوزات، الفواتير، **المفضلة**، الملف الشخصي مع رفع صورة وتغيير كلمة المرور
- تسجيل دخول مع "تذكرني"، تفعيل الحساب بالبريد، واستعادة كلمة المرور

### للإدارة (`admin/`)
- لوحة تحكم بإحصائيات فورية (الإيرادات، الحجوزات، السيارات…)
- إدارة السيارات (إضافة/تعديل/حذف مع صور متعددة)
- إدارة الحجوزات وتغيير حالاتها، إدارة العملاء مع **صفحة تفاصيل لكل عميل**، تقارير، إعدادات

### الأمان
- كلمات المرور بـ **bcrypt** (cost 12)
- حماية **CSRF** في جميع النماذج الحساسة
- قفل مؤقت بعد 5 محاولات دخول فاشلة (15 دقيقة) + سجل محاولات
- جلسات محمية (`httponly`, `samesite`) وتجديد معرف الجلسة عند الدخول
- رفع ملفات آمن: فحص MIME الحقيقي، امتدادات بيضاء، منع تنفيذ PHP في مجلد الرفع

## 🚑 خطأ `SQLSTATE[HY000] [2002] Connection refused` — الحل

هذه الرسالة تعني حرفياً: **لا يوجد خادم MySQL يستمع على العنوان والمنفذ المحدد**.
لا علاقة لها بكلمة المرور ولا بالصلاحيات — الاتصال نفسه لا يصل لخادم.

### 1) اعرف العنوان الذي يحاول الموقع الاتصال به
افتح `install.php`: يظهر في **"تفاصيل بيئة التشغيل"** السطر:
`الخادم: 127.0.0.1:3306 | مصدر الإعدادات: القيم الافتراضية (لم تُضبط أي إعدادات)`.

إذا كان المصدر «القيم الافتراضية» فالمشكلة واضحة: **لم تضبط إعدادات قاعدة البيانات**،
والنظام يستخدم `127.0.0.1` وهو عنوان الجهاز نفسه:

| بيئة التشغيل | لماذا تفشل `127.0.0.1`؟ |
|---|---|
| **Vercel / أي Serverless** | لا يوجد خادم MySQL داخل بيئة التنفيذ إطلاقاً — يجب قاعدة بيانات خارجية |
| **الاستضافة المشتركة (cPanel)** | اسم الخادم يبدأ بـ `localhost` غالباً، لكن يجب إنشاء قاعدة ومستخدم من اللوحة |
| **جهازك (XAMPP/WAMP/MAMP)** | لم تُشغّل خدمة MySQL بعد |

### 2) الحل حسب حالتك

**أ. على Vercel (أو أي استضافة سحابية)**
1. أنشئ قاعدة بيانات MySQL خارجية — مجاناً من [TiDB Cloud Serverless](https://tidbcloud.com)
   (Create Cluster → Serverless → Connect → Generate Password).
2. اضبط المتغيرات (Project → Settings → Environment Variables):
   `DB_HOST` · `DB_PORT=4000` · `DB_NAME` · `DB_USER` (بصيغة `xxxxxxxx.root`) ·
   `DB_PASS` · `DB_SSL=1` · `DB_SESSIONS=1`
3. **أعد النشر (Redeploy)** — المتغيرات لا تُطبَّق على النشر القديم.
4. أعد تحميل `install.php` — سينشئ القاعدة والجداول وحساب المدير.

**ب. على جهازك (XAMPP/WAMP/MAMP)**
1. شغّل MySQL من لوحة التحكم.
2. إن كان خادمك يستخدم Socket مختلفاً، اترك `DB_HOST` فارغاً في النموذج وحدّد
   `DB_SOCKET` (المسار الشائع: `/var/run/mysqld/mysqld.sock` أو
   `/Applications/MAMP/tmp/mysql/mysql.sock`).
3. تأكد من اسم قاعدة البيانات واسم المستخدم (افتراضياً في XAMPP: `root` بدون كلمة مرور).

**ج. على الاستضافة المشتركة (cPanel)**
1. أنشئ قاعدة بيانات ومستخدماً من MySQL Databases واربطهما.
2. استخدم اسم المستخدم/القاعدة الكاملين مثل `user_car_rental`.
3. إن ظهر `Host '...' is not allowed` أضف خادم الموقع في **Remote MySQL**.

### 3) أخطاء قريبة وعلاجها
| الرسالة | السبب | الحل |
|---|---|---|
| `[2002] Connection refused` | لا خادم على `host:port` | صحة `DB_HOST`/`DB_PORT`، تشغيل الخادم، أو قاعدة خارجية |
| `[2002] No such file or directory` | Socket محلي غير موجود | شغّل MySQL أو اضبط `DB_SOCKET` |
| `php_network_getaddresses / getaddrinfo failed` | اسم الخادم غير قابل للتحليل (DNS) | راجع `DB_HOST` (بدون `http://` أو `/`) |
| `[2002] Operation timed out` | جدار ناري أو IP غير مسموح | أضف IP الخادم إلى IP Allowlist |
| `[1045] Access denied` | خطأ في المستخدم/كلمة المرور | على TiDB اسم المستخدم بالشكل `xxxx.root` (لا تحذف ما قبل النقطة) |
| `[1049] Unknown database` | القاعدة غير موجودة | أنشئها من اللوحة (المعالج يحاول إنشاءها تلقائياً) |
| `insecure transport / TLS required` | الخادم يفرض التشفير | أضف `DB_SSL=1` (مطلوب في TiDB Cloud) |
| `[1130] Host is not allowed` | IP الخادم غير مسموح | Remote MySQL / Network Access |

## 🚀 التثبيت (خطوة بخطوة)

### الطريقة الأسهل — معالج التثبيت
1. انسخ مجلد المشروع إلى `htdocs/` (XAMPP) فيصبح المسار: `htdocs/car-rental-system`
2. شغّل Apache و MySQL (من لوحة XAMPP: زر Start بجانب MySQL)
3. افتح في المتصفح:
   ```
   http://localhost/car-rental-system/install.php
   ```
4. يعرض المعالج فحصاً كاملاً للبيئة:
   - إصدار PHP والإضافات المطلوبة
   - **مصدر إعدادات قاعدة البيانات** التي سيستخدمها الموقع فعلياً
   - فحص المنفذ (TCP/DNS) ثم الاتصال الفعلي بقاعدة البيانات
   - تشخيص مفصّل لأي خطأ + خطوات الحل
5. إذا لم تكن الإعدادات مضبوطة، أدخل بيانات الاتصال في النموذج داخل الصفحة واضغط
   **"اختبار وحفظ الإعدادات"** — سيتم إنشاء ملف `config.local.php` (غير مُتتبع في Git)
   ويستخدمه الموقع تلقائياً.
   *(بديل: اضبط متغيرات البيئة `DB_HOST` … وهي تتقدم على الملف.)*
6. بعد ظهور رسالة النجاح ✅: (اختياري) اضغط **"إضافة 15 سيارة تجريبية"**
7. **احذف** `install.php` و`create-tables.php` و`create-admin.php` بعد الانتهاء

> 🛡️ إعادة فتح `install.php` على نظام مثبَّت **لا تحذف بياناتك**: المعالج يكتشف الجداول
> ويتخطى تنفيذ `database.sql` (إعادة التثبيت الكامل متاحة يدوياً بتأكيد صريح فقط).

### الطريقة اليدوية — استيراد SQL
```bash
mysql -u root -p < database.sql
```
ثم (اختيارياً) افتح `add-all-cars.php` لإدراج السيارات التجريبية.

### إعدادات قاعدة البيانات (ترتيب الأولوية)

يقرأ الموقع الإعدادات من **أول مصدر متوفر** بهذا الترتيب (الملف `includes/db-settings.php`):

| # | المصدر | مثال |
|---|---|---|
| 1 | متغيرات البيئة | `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`, `DB_SSL`, `DB_SOCKET`, `DB_CHARSET` |
| 2 | `DATABASE_URL` | `mysql://user:pass@host:4000/dbname` (أو `MYSQL_URL` / `TIDB_DATABASE_URL`) |
| 3 | متغيرات بديلة | `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`, `TIDB_*` |
| 4 | ملف محلي | `config.local.php` (ينشئه معالج التثبيت) أو `includes/db-config.php` |
| 5 | القيم الافتراضية | `127.0.0.1:3306` — تعمل فقط على جهازك المحلي |

يعمل هذا الترتيب **بشكل موحّد** في الموقع ومعالج التثبيت، لذلك ما تراه في صفحة التشخيص
هو بالضبط ما يستخدمه الموقع. لحفظ الإعدادات يدوياً:

```php
<?php
// config.local.php
return [
    'host'     => '127.0.0.1',
    'port'     => '3306',
    'name'     => 'car_rental_db',
    'user'     => 'root',
    'pass'     => '',
    'ssl'      => false,
    'charset'  => 'utf8mb4',
];
```

> 💡 اضبط `DB_SOCKET` فقط عند استخدام Socket محلي (MAMP / بعض حزم Linux).

## ☁️ النشر على Vercel (loc-voi.vercel.app)

المشروع مهيأ للعمل على Vercel عبر ملف `vercel.json` (runtime: `vercel-php@0.9.0`)،
مع جلسات محفوظة في قاعدة البيانات تلقائياً عند العمل على Vercel.

### الخطوات
1. **أنشئ قاعدة بيانات MySQL خارجية** (مجاناً مثلاً عبر [TiDB Serverless](https://tidbcloud.com) — متوافق مع MySQL) وسجّل بيانات الاتصال.
2. من [vercel.com](https://vercel.com) → **Add New → Project** → استورد مستودع GitHub هذا.
3. في شاشة الإعدادات:
   - **Project Name**: `loc-voi` (سيكون جزءاً من النطاق `loc-voi.vercel.app`)
   - أضف **Environment Variables**:

   | المتغير | القيمة |
   |---|---|
   | `DB_HOST` | عنوان خادم قاعدة البيانات (من مزوّد خارجي — لا تستخدم `127.0.0.1`) |
   | `DB_PORT` | `4000` في TiDB Cloud Serverless، و`3306` في MySQL العادي |
   | `DB_NAME` | اسم قاعدة البيانات |
   | `DB_USER` | اسم المستخدم (`xxxxxxxx.root` في TiDB Cloud) |
   | `DB_PASS` | كلمة المرور |
   | `DB_SSL` | `1` إذا كان الخادم يفرض TLS (مطلوب في TiDB Cloud) |
   | `DB_SESSIONS` | `1` (جلسات في قاعدة البيانات بدل الملفات) |

   *(أو متغير واحد `DATABASE_URL` بصيغة `mysql://user:pass@host:port/dbname`)*
   ➡️ **بدون قاعدة بيانات خارجية + هذه المتغيرات سيفشل الاتصال برسالة `Connection refused`
   لأن Vercel لا يوفّر خادم MySQL محلياً.**
4. اضغط **Deploy**.
5. بعد اكتمال النشر افتح `https://loc-voi.vercel.app/install.php` مرة واحدة لإنشاء الجداول وحساب المدير.
6. افتح `https://loc-voi.vercel.app/add-all-cars.php` لإضافة السيارات التجريبية.

### 🧨 إذا ظهر الموقع كأكواد PHP بدل تشغيله (المشكلة الأكثر شيوعاً)

**العلامة:** تظهر في الصفحة أسطر مثل `<?php echo SITE_NAME; ?>` كنص عادي، وأحياناً تظهر روابط غريبة
فيها `%3C?php`.

**المعنى:** المنشور لا يشغّل PHP إطلاقاً، ويخدم ملفات `.php` كملفات ثابتة (نص). الكود سليم —
المشكلة في إعداد النشر فقط.

**تحقق في 5 ثوانٍ:** افتح

```
https://your-site.com/ping.php
```

- النتيجة السليمة: `{ "php_running": true, ... }`
- إذا ظهر الملف نفسه كنص/كود: PHP لا يعمل على هذا النشر.

**⚡ الطريقة الأسرع للعمل الآن (بدون Vercel):**

```bash
docker compose up -d
# ثم افتح:  http://localhost:8080/install.php
```

هذا يشغّل الموقع + MySQL معاً بأمر واحد على أي جهاز فيه Docker (وتعمل نفس الصورة على
Railway / Render / Fly.io / VPS). التفاصيل في قسم «🐳 التشغيل بـ Docker» أدناه.

**قائمة الإصلاح على Vercel (بالترتيب):**

1. **اختر النشر الصحيح**: `Project → Deployments` واحرص أن أحدث نشر في **Production** هو من آخر
   `main`. إن كان النشر الحالي قديماً: من القائمة `⋯` → **Promote to Production** (أو Redeploy).
2. **إصدار Node**: `Settings → General → Node.js Version` اجعله **24.x**
   (runtime `vercel-php@0.9.0` يُبنى لدالة `nodejs24.x`؛ إصدار Node مختلف قد يُسقط الدالة بصمت).
3. **إعدادات البناء**: `Settings → Build & Development`
   - Framework Preset: **Other**
   - Build Command: **فارغ**
   - Output Directory: **فارغ**
   - Install Command: **فارغ**
4. **أعد النشر بدون كاش**: `Deployments → آخر نشر → Redeploy` مع إلغاء **Use existing Build Cache**.
5. **تأكد من إنشاء الدالة**: في صفحة النشر نفسه افتح تبويب **Functions / Output** — يجب أن ترى
   `api/index.php` بـ `vercel-php@0.9.0`. إن لم تظهر، فبناء الدالة فشل (اقرأ الـ Build Log).
6. أعد فتح `/ping.php` — يجب أن يظهر JSON.

> ⚠️ مهم: في `vercel.json` تُرسل قائمة `routes` **كل** الطلبات إلى `api/index.php` (نقطة تشغيل PHP)
> وهذا مقصود. لا تُضِف `{ "handle": "filesystem" }` قبلها، لأنها ستجعل Vercel يخدم ملفات `.php`
> كملفات ثابتة = نفس المشكلة تماماً. الملفات الثابتة (CSS/JS/الصور) يخدمها الراوتر نفسه.

> 💡 إن تعذّر تشغيل PHP على Vercel (أو أردت استضافة تدعم الملفات المرفوعة والبريد): النظام PHP عادي
> ويعمل على أي استضافة PHP + MySQL، أو على VPS/Docker باستخدام صورة `php:8.3-apache`.

> 📌 ملف `package.json` موجود فقط لتثبيت إصدار Node على **24.x** (انظر الخطوة 2 أعلاه) — لا تبعيات
> JavaScript في المشروع ولا خطوة بناء.

### قيود يجب معرفتها على Vercel
- **الصور المرفوعة** من لوحة الإدارة تُمحى مع كل عملية نشر جديدة (نظام الملفات مؤقت) — للاستخدام الجاد استخدم تخزيناً خارجياً (S3 ونحوه) أو انشر على استضافة PHP+MySQL تقليدية.
- **إرسال البريد** عبر `mail()` لا يعمل على Vercel — روابط التفعيل تُسجل في سجلات الأخطاء؛ استخدم خدمة SMTP عند الحاجة.
- `.htaccess` لا يُطبق على Vercel (تُستخدم إعدادات `vercel.json` بدلاً منه).

## 🐳 التشغيل بـ Docker (موصى به إن لم يعمل Vercel)

الطريقة الأضمن: PHP عادي + Apache + MySQL، بلا قيود Serverless (الصور المرفوعة تبقى محفوظة،
والبريد `mail()` متاح داخل الحاوية).

```bash
# 1) تشغيل الموقع + قاعدة البيانات
docker compose up -d

# 2) انتظر ~20 ثانية حتى تجهز قاعدة البيانات، ثم افتح:
#    http://localhost:8080/install.php

# 3) بعد نجاح التثبيت: http://localhost:8080  ولوحة الإدارة /admin

# أوامر مفيدة
docker compose logs -f web     # متابعة السجلات
docker compose down            # إيقاف (البيانات تبقى محفوظة)
docker compose down -v         # إيقاف + حذف قاعدة البيانات والصور المرفوعة
```

- بيانات قاعدة البيانات الافتراضية داخل Docker موجودة في `docker-compose.yml`
  (`DB_USER=car_rental` / `DB_PASS=car_rental_pass`) — **غيّرها قبل أي نشر عام**.
- ملف `docker/php.ini` يضبط حدود رفع الملفات والمنطقة الزمنية.
- لنشر هذه الصورة على سيرفر: `docker compose up -d` على السيرفر نفسه مع نطاق وHTTPS
  (أو استخدم منصة تدعم Docker مثل Railway/Render وأضف نفس متغيرات البيئة).

## 🔒 ملاحظات النشر في الإنتاج

0. لا ترفع `config.local.php` إلى Git (مُستثنى في `.gitignore`) — الإعداد الدائم للإنتاج يكون عبر متغيرات البيئة.
1. اجعل في `includes/config.php`: `define('DEBUG_MODE', false);`
2. احذف سكربتات التثبيت والفحص: `install.php`, `create-tables.php`, `create-admin.php`, `seed-cars.php`, `add-all-cars.php`, `download-images.php`, `create_structure.php`, `ping.php`
3. فعّل HTTPS (الموقع يفعّل كوكيز آمنة تلقائياً معه)
4. اضبط `SITE_URL` يدوياً إن لم يُكتشف تلقائياً
5. اضبط إعدادات البريد الحقيقي (الدالة `send_email` في `config.php`) أو استبدلها بـ PHPMailer/SMTP

## 🛠️ استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `Connection refused [2002]` | راجع قسم «🚑 خطأ Connection refused» أعلاه |
| "تعذر الاتصال بقاعدة البيانات" | افتح `install.php` — يعرض مصدر الإعدادات والخطأ المشخّص |
| التغييرات في متغيرات البيئة لا تُطبَّق | أعد النشر (Redeploy) أو أعد تشغيل الخادم |
| صفحة بيضاء فارغة | فعّل `DEBUG_MODE => true` مؤقتاً في `includes/config.php` |
| فشل رفع الصور | تحقق أن مجلد `uploads/` قابل للكتابة (على Vercel استخدم تخزيناً خارجياً) |
| الصور التجريبية لا تظهر | تحتاج اتصال إنترنت (مأخوذة من Unsplash) |
| `نظام مثبَّت مسبقاً` في المعالج | طبيعي: بياناتك محفوظة. لإعادة التثبيت من الصفر استخدم قسم «إعادة تثبيت كاملة» |
| لا يمكن حفظ `config.local.php` | نظام الملفات للقراءة فقط (Vercel) — استخدم متغيرات البيئة |
